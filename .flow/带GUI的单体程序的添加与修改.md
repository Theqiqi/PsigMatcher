## 1. 查看 git 内容

目标     : 查看当前目录的 git 状态：是否已初始化、当前分支、已跟踪/未跟踪文件、最近提交历史、工作区是否干净
前置     : 当前项目目录（可能尚未初始化 git）
解构     : 观察 [是否已初始化 / 当前分支 / 已跟踪/未跟踪文件 / 最近提交历史 / 工作区是否干净]
产物     : git 现状报告
约束     : 执行 `git status` / `git log --oneline -5`（未初始化时 git 会提示 not a git repository，属正常现象，如实记录）；记录结论：①已初始化？②当前分支与最近提交；③工作区是否有未提交改动；④.flow/design 等目录是否已被跟踪；只查看，不修改任何文件；本阶段在**任何编写/修改开始之前**执行，且每个步骤都要用 git 保存进度；注意：每个「git 保存」都应在该步骤产物完成后执行（文档/代码编写完成后即提交，而非等全部做完）
排除项   : 不超出本步 目标 范围；不做 后续 步骤 的工作
完成标准 : git 现状报告 产出且 约束 逐条 满足；产物 落盘后 执行 git 保存：本步骤只读不产生改动，无需提交；结论记入流程日志后进入下一步。

## 2. 判断未初始化 git 则先初始化 git

目标     : 若「查看 git 内容」判定未初始化（git status 报 not a git repository），执行 `git init` 初始化仓库；已初始化则跳过
前置     : 「查看 git 内容」的 git 现状报告
解构     : 观察 [若「查看 git 内容」判定未初始化（git status 报 not a git repository） / 执行 `git init` 初始化仓库；已初始化则跳过]
产物     : 已初始化的 git 仓库（或确认已初始化）
约束     : 仅在确认未初始化时执行 `git init`，初始化后再次 `git status` 确认仓库可用；初始化只建仓库不提交（.gitignore 尚未建立，见「编写 .gitignore」步骤）
排除项   : 不超出本步 目标 范围；不做 后续 步骤 的工作
完成标准 : 已初始化的 git 仓库（或确认已初始化） 产出且 约束 逐条 满足；产物 落盘后 执行 git 保存：本步骤可能产生 `.git/` 目录；仓库建立后暂不提交，等「编写 .gitignore」步骤建立 .gitignore 后统一做首次提交。

## 3. 编写 .gitignore（参考当前目录的 .gitignore）

目标     : 编写或更新根目录 .gitignore，忽略构建产物、IDE 配置、临时文件等，**参考现有目录的 .gitignore 内容**，在其基础上按需增补
前置     : 当前目录已有的 .gitignore（若存在）、git 仓库
解构     : 观察 [编写或更新根目录 .gitignore / 忽略构建产物、IDE 配置、临时文件等 / **参考现有目录的 .gitignore 内容** / 在其基础上按需增补]
产物     : 根目录 .gitignore
约束     : 必须参考现有 `.gitignore`（当前项目已有一份，覆盖 out、*.exe/*.lib/*.obj/*.log、.vs/、.idea/、vcpkg_installed、cmake-build-* 等），不得凭空重写；增补项按需：新增目录的产物（如新程序的 out/）、临时调试文件、截图/日志等；编写后执行 `git status --short` 确认被忽略文件不再出现在未跟踪列表
排除项   : 不超出本步 目标 范围；不做 后续 步骤 的工作
完成标准 : 根目录 .gitignore 产出且 约束 逐条 满足；产物 落盘后 执行 git 保存：`.gitignore` 就绪后执行首次提交：`git add .gitignore && git commit -m "chore: 初始化 gitignore"`。

## 5. 用 git 保存进度（基线提交）

目标     : 在进入流程步骤前把当前项目全量状态保存为基线提交，便于后续每步对照 diff
前置     : 已初始化的仓库、已就绪的 .gitignore
解构     : 观察 [在进入流程步骤前把当前项目全量状态保存为基线提交 / 便于后续每步对照 diff]
产物     : 基线提交（clean 工作区）
约束     : 执行 `git add -A && git commit -m "chore: 基线进度"`（首次）或确认工作区已 clean（已有历史时）；提交后 `git status` 应显示 clean；若有未跟踪文件且不属于 .gitignore 应处理（纳入跟踪或补 .gitignore）；每个步骤完成后必须用 git 保存进度（步骤末尾「git 保存」行），不允许跨多个步骤才提交一次；提交信息格式建议：`类型: 内容`（chore/docs/feat/fix/test），与步骤名对应；修改模式沿用既有仓库历史；新建模式按「查看 git 内容」至「确定版本号」各步初始化后从基线提交开始；提交前可用 `git status --short` 确认只包含本步骤产物；误提交可用 `git reset --soft HEAD~1` 撤销（保留改动）
排除项   : 不超出本步 目标 范围；不做 后续 步骤 的工作
完成标准 : 基线提交（clean 工作区） 产出且 约束 逐条 满足；产物 落盘后 执行 git 保存：本步骤本身即提交；此后每个步骤末尾都必须再次 git 保存进度（见各步骤「git 保存」行）。
