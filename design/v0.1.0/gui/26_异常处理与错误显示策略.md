# 26 异常处理与错误显示策略文档

- 版本：v0.1.0
- 前置：`21_职责和边界.md`

## 1. 原则

- 后台线程（QtConcurrent）中的异常不得跨线程抛出；必须通过 `QFutureWatcher` 信号或 `QFuture::onFailed` 传回主线程。
- 静态库公共 API 本身不抛异常（用返回值/出参表达错误），GUI 侧再按错误类型呈现。
- 所有 UI 更新在主线程执行。

## 2. 错误分类与显示

| 错误 | 来源 | 呈现 |
| --- | --- | --- |
| 输入非法（模式串非法、未选进程、结果为空） | 校验 | 状态栏瞬时反馈（红字）；不弹窗 |
| 文件 I/O 失败（导入/导出失败） | 静态库返回 false/err | 状态栏瞬时反馈（红字）；影响决策时弹窗 |
| 枚举/扫描失败（权限不足、异常） | 后台任务 | QFutureWatcher::finished 后检查，状态栏/弹窗 |
| 后台任务抛出 C++ 异常 | QtConcurrent | 经 QFutureWatcher 捕获（`watcher->isCanceled()/result()` 保护），不跨线程传播 |

## 3. 后台任务异常回传模式

```cpp
auto future = QtConcurrent::run([this]() -> std::vector<psig::MatchResult> {
    try {
        return psig::ScanProcesses(req, cb, &m_cancel);
    } catch (const std::exception& e) {
        // 转换为错误状态，由主线程读取
        m_lastError = e.what();
        return {};
    }
});
m_scanWatcher->setFuture(future);
// finished 槽（主线程）读取结果，如 m_lastError 非空则显示错误
```

- 禁止在 lambda 中直接调用 QWidget 方法；进度回调经 `Qt::QueuedConnection` 或 `QMetaObject::invokeMethod` 回主线程更新进度条。

## 4. 弹窗策略

- 需要用户决策（覆盖确认、清空确认、无权限提示）→ QMessageBox。
- 短暂错误 → 状态栏瞬时反馈，不弹窗。
- 同一错误只在一个位置呈现。

## 5. 约束满足说明

- 后台线程异常经 QFutureWatcher/信号传主线程，不跨线程抛异常。
