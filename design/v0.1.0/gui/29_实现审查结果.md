# 29 实现审查结果（步骤 45–85）

- 版本：v0.1.0
- 前置：`21_职责和边界.md`、`22_View层接口.md`、`23_Model层接口.md`、`24_ViewModel接口.md`、`25_静态库API调用映射.md`、`28_QtGUI代码规范.md`
- 说明：本文件逐条记录 GUI 入口系统流程第 45–85 步的审查结论与证据。审查对象为 `gui/src` 生产代码与 `gui/test` 测试代码。结论均为「通过」。

## 证据基线

- 生产代码位置：`gui/src/{view,model,viewmodel}`、`gui/src/main.cpp`
- 测试代码位置：`gui/test/{target,unit,integration}`
- 关键 grep 证据（均无命中）：
  - `windows.h|tlhelp32|OpenProcess|ReadProcessMemory` in `src/` → 无
  - `findChild` in `src/` → 无
  - `signals:|slots:|Q_SIGNALS|Q_SLOTS` in `src/view/` → 无
  - `connect(` in `src/view/` → 无
  - `#include "../` in `src/`、`test/` → 无
  - `#include <boost|<gtest|<sqlite` in `src/` → 无

## 45. View 纯净检查 — 通过

- View 仅创建控件、布局、样式；`src/view/` 无 `signals:`/`slots:`/`Q_SIGNALS`/`Q_SLOTS`，无 `connect(`，无事件处理逻辑。
- View 头文件不 include ViewModel/静态库：`mainwindow.h` 仅依赖 `<QMainWindow>` 与前置声明；各页面头文件仅依赖 Qt 与 Model 层类型（`model/types.h`）。
- View 不知道 ViewModel 存在：无 ViewModel 类型引用。

## 46. View 独立编译检查 — 通过

- 独立测试目标 `psig_test_view`（`test/unit/CMakeLists.txt`）只链接 `Qt6::Widgets Qt6::Test GTest`，源文件仅 View + Model，不链接 ViewModel 与 `psig`；Debug/Release 均编译链接通过。

## 47. ViewModel 指针操控检查 — 通过

- `MainViewModel` 持有 `MainWindow* m_view`（绑定引用不拥有，初始化为 `nullptr`），经 `install(MainWindow*)` 注入。
- 页面指针经 View 公开 getter 获取（`m_view->signaturePage()` 等），不缓存 View 私有成员。
- Model 指针 `m_sigModel/m_procModel/m_resultModel` 由 VM `new`（parent=this）并负责生命周期。
- 无 `findChild`，不访问 View 私有成员；仅经公开 getter 读控件、公开 UI 方法更新界面。

## 48. 后台执行检查 — 通过

- 耗时操作（枚举进程、扫描）经 `QtConcurrent::run` 后台执行；主线程无 `QThread::wait()`。
- `MainViewModel::~MainViewModel` 仅在析构时 `waitForFinished()` 回收后台任务，属退出路径，非主线程阻塞热路径。

## 49. Model 纯净检查 — 通过

- Model 仅 `#include` Qt（`QAbstractTableModel`/`QString`/`QStringList`/`QtGlobal`）、`model/types.h` 与标准库；不含业务逻辑、不 include `psig.h`。
- 只做 `data()/setData()/flags()/headerData()` 与行集合维护。

## 50. 事件链接检查 — 通过

- 全部控件信号（`QPushButton::clicked`、`QLineEdit::textChanged`、`QAction::triggered`、`QFutureWatcher::finished`）都在 ViewModel 的 `install()/bind*()` 中 connect；View 侧零连接。
- 每个用户可达控件均有对应绑定，无重复 connect。
- `main.cpp` 顺序为：创建 View → 创建 ViewModel → `install(&view)` → `show()` → `exec()`。

## 51. View 页面拆分检查 — 通过

- 页面拆分为独立类独立文件：`SignatureEditorPage`、`ProcessSelectionPage`、`ResultPage`、`ColumnManagerDialog`，各含独立 `.h/.cpp`。
- `MainWindow` 仅做骨架：`QStackedWidget` + 菜单/工具栏 + 状态栏/日志，不内联堆叠页面控件。
- 页面切换经 `MainWindow::showSignaturePage()/showProcessPage()/showResultPage()`（内部 `setCurrentIndex`）由 ViewModel 调用。

## 52. View 控件 getter 暴露检查 — 通过

- 每个需绑定控件均有公开 getter（如 `SignatureEditorPage::addRowBtn()`、`ProcessSelectionPage::filterEdit()`、`ResultPage::exportCsvBtn()`）。
- 每个界面更新均有公开 UI 方法（如 `setModel()`、`setPersistentStatus()`、`setTransientMessage()`、`setProgress()`、`appendLog()`）。
- 控件指针构造时创建、唯一归属 View，getter 只读不转让所有权；无 `findChild` 访问交互控件。

## 53. connect 绑定归属检查 — 通过

- 全部绑定位于 ViewModel 层；`main.cpp` 固定五步流程；View 构造函数无业务 connect；View 无 signals/private slots；页面切换由 VM 调 View 公开方法完成。

## 54. 布局与交互合理性审查 — 通过

- 特征码表为可编辑表格 + 「新增行/删除行/管理列」按钮（批量操作），元素级删除经选中行批量执行，非单行输入框。
- 进程选择页为表格 + 多选（`ExtendedSelection`），支持过滤与全选。
- 结果页为只读表格（`NoEditTriggers`），仅导出/清空入口，无直接改数据入口。
- 反馈分区：状态栏持久状态（`persistentLabel`）+ 瞬时消息（`transientLabel`）+ 独立日志区（`logEdit`），职责不混。

## 55. main 职责检查 — 通过

- `main.cpp` 仅：创建 `QApplication`、加载样式/图标、创建 View、创建 ViewModel、`install`、`show`、`app.exec()`；无业务逻辑。

## 56. View 职责检查 — 通过

- 同 45/46：View 只做 UI 绘制与布局，无业务逻辑。

## 57. Model 职责检查 — 通过

- 同 49：Model 只做数据管理，无业务逻辑。

## 58. ViewModel 职责检查 — 通过

- ViewModel 只做「事件 → 调静态库 → 更新 Model/View」，不绘制 UI、不管理数据存储细节（交给 Model）。

## 59. 静态库 API 真实性检查 — 通过

- ViewModel 调用的 API 全部真实存在于 `psig/include/psig.h`：`EnumerateProcesses`、`ParsePattern`、`ScanProcesses`、`RequestCancel`、`BuiltinSignatureColumns`、`ImportSignaturesCsv/Db`、`ExportSignaturesCsv/Db`、`ExportResultsCsv/Db/Txt`；与 `25_静态库API调用映射.md` 一致，无编造。

## 60. 静态库隔离检查 — 通过

- `psig` 为无 Qt 依赖的 C++ 静态库（仅 Windows API + vendored SQLite）；GUI 仅经 `psig.h` 公开 API 调用，不引用内部头文件。

## 61. 数据审查（真实数据与接口来源） — 通过

- 生产代码无 `mock/fake/dummy/sample`、无写死扫描/进程/读写结果；每项能力可追溯到 `psig` 真实公共 API。
- 已知测试值仅存在于测试目标 `gui/test/target/main.cpp` 与测试代码，不被生产目标链接。

## 62. 重复实现检查 — 通过

- ViewModel 未自行实现进程枚举/内存读取/地址搜索/特征码解析，全部委托 `psig` API；VM 仅做类型转换与 UI 编排。

## 63. 平台相关与第三方库检查 — 通过

- 生产代码无 `windows.h`/`tlhelp32.h`/WinAPI；无 Qt 以外第三方库；依赖范围仅 Qt6::Widgets/Qt6::Concurrent + `psig` 公共 API + C/C++ 标准库。

## 64. 异步执行检查 — 通过

- 耗时操作经 `QtConcurrent::run` + `QFutureWatcher` 异步；结果经 `finished` 信号回主线程更新 Model/View。

## 65. 生命周期检查 — 通过

- View 与 ViewModel 在 `main.cpp` 栈上创建，声明顺序 View 先于 ViewModel（销毁顺序相反，VM 先销毁），VM 析构时回收后台任务，不会在 View 之后仍持有失效 View 指针。
- Model 由 VM 持有（parent=this），随 VM 销毁。

## 66. 跨线程异常检查 — 通过

- 后台任务返回 `std::vector<...>`（`psig` API 不抛异常，返回结果/错误码）；结果经 `QFutureWatcher::finished` 在主线程读取，无跨线程直接触碰 UI。
- 扫描进度经 `QMetaObject::invokeMethod(..., Qt::QueuedConnection)` 投递回主线程。

## 67. 输入校验检查 — 通过

- 特征码文本经 `psig::ParsePattern` 校验，非法模式提前返回并提示行号。
- 进程过滤框文本 `trimmed()` 后比较，空串表示不过滤；扫描前校验「模式非空」「已选进程」。

## 68. 内存管理检查 — 通过

- Model/Watcher 均设 `parent=this`（VM），由 Qt 父子关系自动回收；View 控件由布局/父控件回收；无裸 `new` 泄漏。

## 69. 资源路径检查 — 通过

- `main.cpp` 引用 `:/style.qss`、`:/app.png`；`res/resources.qrc` 前缀 `/`，文件 `style.qss`、`app.png` 存在且路径一致。

## 70. 空指针检查 — 通过

- `install(MainWindow*)` 首行判空返回；各 `bind*()` 经 getter 获取的非空控件使用；Model getter 使用前判空。

## 71. 嵌套深度检查 — 通过

- 各函数嵌套均不超过三重；`onStartScan` 的进度回调经 `invokeMethod` 拉平，避免深嵌套。

## 72. 提前返回检查 — 通过

- 错误/取消路径均提前返回：导入/导出失败、扫描无模式、未选进程、清空取消等均 `return`，不做无意义后续执行。

## 73. 头文件越界检查 — 通过

- ViewModel 依赖 View 的公开接口（getter/公开方法）与 Model 头文件，不依赖 View 私有实现；View 不 include ViewModel/静态库头文件。

## 74. 单一职责检查 — 通过

- 每个函数职责单一：`bind*()` 只做绑定、`on*()` 只处理一类事件、转换辅助函数只做类型转换。

## 75. 规范审查 — 通过

- 命名、缩进、`QStringLiteral` 使用、`#pragma once`、`Q_OBJECT` 宏、成员 `m_` 前缀等符合 `28_QtGUI代码规范.md`。

## 76. 独立子目录检查 — 通过

- `gui/` 与 `psig/` 在根目录平级、互不嵌套；GUI 不在静态库目录内，静态库不在 GUI 目录内。

## 77. 项目自包含检查 — 通过

- `gui/` 拥有自己的 `CMakeLists.txt`、`CMakePresets.json`、`vcpkg.json`、`script/`、`out/`；`psig/` 同样自包含；两者不共享构建配置或产物目录。

## 78. 根目录配置隔离检查 — 通过

- 根目录无 `CMakeLists.txt`/`CMakePresets.json`；构建配置分属 `gui/` 与 `psig/`。

## 79. 构建产物归属检查 — 通过

- 构建输出 `gui/out/`、`psig/out/` 位于各自项目内；`script/` 位于各项目内；无根级/共享 `workspace/`；`psig` 无 `install/` 与安装脚本；GUI 未配置 `install/`（发布需要时再建）。

## 80. 三方依赖归属检查 — 通过

- 检测到 vcpkg（VCPKG_ROOT 指向 VS2022 自带 vcpkg）；`gui/vcpkg.json` 与 `psig/vcpkg.json` 以 vcpkg manifest 管理 `gtest`；Qt6 走独立安装（QT6_DEBUG_DIR/QT6_RELEASE_DIR），不纳入 vcpkg。无 vendored 三方源码（`psig/third_party/sqlite3` 为静态库自身实现依赖，不属 GUI 三方依赖）。

## 81. 跨项目依赖检查 — 通过

- GUI 经 `find_library(PSIG_LIB ... ../psig/out/lib/<配置>)` 直接引用拥有方产物，公共头来自 `../psig/include`；无复制源码、无 install/ 中间层、无共享/根级目录。

## 82. 测试层级检查 — 通过

- 单元测试逐层：`test_model`（data/setData）、`test_view`（View 公开方法）、`test_viewmodel`（槽/事件链接/静态库调用链）、`test_errordialog`（弹窗）。
- 集成测试 `test_mvvm_flow` 走通完整链路：View 信号 → VM 槽 → `psig` API → Model → View 刷新，不跳层。
- 用户流程测试 `test_user_flow` 以用户视角断言真实业务结果（导入/导出/扫描/三格式导出）。
- E2E 见 `test/e2e/`，真实启动 `psig_gui.exe`。

## 83. e2e 独立性检查 — 通过

- E2E 脚本位于 `gui/test/e2e/`，与 unit/integration 同属 `test/`，但目录内不含 `CMakeLists.txt`、未注册进 CMake，独立以 `bash gui/test/e2e/verify_all.sh` 运行。

## 84. 测试非空检查 — 通过

- 各测试 CMakeLists 注册可编译运行的 gtest 目标；源码含真实 `TEST(...)` 用例（Model 6、View 6、ViewModel 5+错误弹窗 2、MVVM 2、用户流程 8），均实际运行并断言真实结果。

## 85. 头文件包含风格检查 — 通过

- 所有 `#include` 均为 `名字/名字` 或标准库形式（`model/types.h`、`view/mainwindow.h`、`viewmodel/mainviewmodel.h`、`psig.h`、`unit/test_app.h`）；无 `../` 相对路径。搜索路径由各 `CMakeLists.txt` 的 `target_include_directories()` 提供。

## 结论

第 45–85 步全部通过，无需回跳。
