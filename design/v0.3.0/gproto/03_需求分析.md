# 03 需求分析（psig v0.3.0）

> 前置：`02_跨流程需求接收.md`、`design/v0.2.4/gproto/77_静态库完成契约.md`（基线）
> 模式：修改型，增量分析。

## 1. 领域模型（增量）

| 概念 | 变更 |
| --- | --- |
| 扫描进度 `ScanProgress` | `done`/`total` 语义由「模式计数」改为「工作量（区域）计数」 |
| 扫描执行 `ScanProcesses` | 由「进程×区域双重串行」改为「区域级并行」 |
| 进度回调 `ProgressCallback` | 触发粒度由「每 1MiB 块」改为「每区域」；可能被多线程并发调用 |

## 2. 需求点（自然语言 → 需求）

- **R-1**：进度回调报**真实工作量进度**：`total` = 目标进程可读区域总数，`done` = 已完成区域数，单调递增至 `total`。
- **R-2**：以**内存区域**为并行单位多线程扫描，缩短总耗时；结果/进度/取消并发安全。
- **R-3**：进度回调**按区域触发**（不再按 1MiB 块），显著降低回调次数。

## 3. 非功能需求

- 不抛异常，用返回值/出参表达错误；线程安全（沿用）。
- 向后兼容：`ScanProcesses` 签名不变；命中判定、结果字段、导出格式不变。
- **不依赖 Qt**：并行只能用标准库线程设施（`std::thread` + `std::atomic`/`std::mutex`）。
- 只读：扫描不修改目标进程。
