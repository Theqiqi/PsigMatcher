| 对象 | 变更 | 说明 | 关键属性 |
| --- | --- | --- | --- |
| 扫描任务 ScanTask | **修改** | 进度语义由「模式计数」改为「工作量进度」，并引入区域并行 | 目标进程集合、特征码集合、**进度（已完成工作量/总工作量）**、状态 |

> 本次改动**不涉及任何数据集合的元素与操作**，只涉及**扫描任务（ScanTask）的执行方式与进度语义**。

## 2. 数据集合（增量更新）

### 集合 E：历史日志 LogCollection
- 不变（引用 v0.1.0）。**进度不写入日志**（日志仅保留扫描开始/结束行）。

### 扫描任务 ScanTask（**执行语义修改**，非数据集合）
- **修改 1（进度语义）**：进度由「已处理模式数 / 总模式数」改为「**已完成工作量 / 总工作量**」。
  - 工作量单位取「内存区域」（与并行单位一致）：`总工作量 = 所有目标进程的可读区域数之和`（或按区域字节数加权，见设计阶段）。
  - 进度应随扫描推进**单调增长**：开始≈0%，结束=100%；单进程多区域时也能平滑变化。
- **修改 2（执行方式）**：由「进程×区域双重串行」改为「**区域级并行**」。
  - 并行单位 = 单个内存区域（区域之间相互独立、只读）。
  - 命中结果、进度计数、取消标志在各工作线程间**并发安全**地汇聚。
  - 并行度按可用 CPU 自适应（不引入外部线程池依赖）。
- **不变**：命中判定算法、结果字段、导出格式、取消语义均不变。

## 4. 操作流程（高层，增量）

1. 维护特征码（不变）。
2. 选择目标进程（多选，不变）。
3. **批量扫描（修改）**：预统计总工作量 → 按区域并行扫描 → 工作线程更新原子进度 → 界面定时采样显示真实进度 → 产出结果表。
4. 查看/导出结果（不变）。
