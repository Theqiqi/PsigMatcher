# 04 GUI 需求分析（需求变更文档，v0.3.0）

> 模式：修改型。逐条列出「改动点 → 新增/修改/删除 → 影响窗口/功能」，并给出窗口布局、用户操作路径（点击流程）、可视化反馈要求。未提及的窗口/功能沿用 v0.2.4。

## 变更总览

| 编号 | 改动点 | 类型 | 影响窗口/功能 |
| --- | --- | --- | --- |
| C-01 | 扫描进度条恒为 100% | 修改（缺陷修复） | 状态栏 → 扫描进度条 |

## C-01 进度条反映真实进度

- **改动点 → 类型**：进度数值语义修正 → **修改**（缺陷修复）。
- **现状**：`psig` 在进度回调中把 `sp.done` 与 `sp.total` 都赋为特征码个数，GUI `pct = sp.done * 100 / sp.total` 恒为 100%。
- **新增/修改/删除**：**修改**进度语义为「已完成工作量 / 总工作量」：
  - `total` = 本次扫描的总工作量（所有目标进程的可读内存区域数之和；区域字节加权见设计阶段）；
  - `done` = 已完成的工作量，随扫描推进**单调递增**；
  - GUI 进度条按 `done/total` 显示，开始≈0%、结束=100%。
- **影响窗口/功能**：状态栏扫描进度条（`QProgressBar`）。涉及 psig `ScanProgress` 语义、GUI `MainViewModel::onStartScan` 的取值。
- **窗口布局**：不变（状态栏仍为 左持久状态 / 中进度条 / 右瞬时文字）。
- **用户操作路径（点击流程）**：选择进程 → 点击「扫描」→ 观察状态栏进度条由 0% 平滑增长至 100%。
- **可视化反馈**：进度条随扫描真实推进；单进程多区域时也平滑变化，不再一出现即满格。
- **验收**：扫描开始时进度接近 0%，结束为 100%；中途数值介于两者之间且单调不减；扫描量越大停留越久。

## C-02 按内存区域并行扫描

- **改动点 → 类型**：扫描执行方式 → **修改**（性能改进）。
- **现状**：`ScanProcesses()` 对目标进程串行；`ScanOneProcess()` 内对区域串行。多核未利用。
- **新增/修改/删除**：**修改**扫描执行为**区域级并行**：
  - 并行单位 = 单个内存区域（区域相互独立、只读）；
  - 多个工作线程并发扫描；命中结果、进度计数、取消标志并发安全；
  - 并行度按可用 CPU 自适应，不引入外部线程池依赖。
- **影响窗口/功能**：无可见 UI 变更；表现为**扫描更快**。涉及 psig `ScanProcesses`/`ScanOneProcess`/`ScanRegion` 内部实现。
- **窗口布局**：不变。
- **用户操作路径（点击流程）**：选择进程 → 点击「扫描」→ 更快得到结果。
- **可视化反馈**：无新增控件；进度条推进更快。
- **验收**：多核机器上，同一（进程 × 特征码）任务，并行版本总耗时明显低于 v0.2.4 串行版本；**命中结果集合与串行版本一致**（数量与内容相同，顺序可不同）。

## C-03 定时器采样进度

- **改动点 → 类型**：界面刷新机制 → **修改**（性能改进）。
- **现状**：`viewmodel/scan.cpp` 的进度回调每被调用一次就 `QMetaObject::invokeMethod(..., Qt::QueuedConnection)` 投递一次界面更新。
- **新增/修改/删除**：**修改**为**定时器采样**：
  - 工作线程只更新进度原子变量；
  - GUI 主线程用 `QTimer`（约 100~200ms）定期读取原子变量并刷新状态栏；
  - 界面刷新频率与扫描循环解耦，扫描不再被高频界面事件拖慢。
- **影响窗口/功能**：状态栏进度条与瞬时文字。涉及 GUI `MainViewModel::onStartScan`（定时器 + 原子变量）。
- **窗口布局**：不变。
- **用户操作路径（点击流程）**：选择进程 → 点击「扫描」→ 进度以稳定频率（约 5~10 次/秒）刷新。
- **可视化反馈**：进度条按固定节拍更新，扫描过程流畅。
- **验收**：扫描期间界面进度按定时器节拍刷新（非逐块刷新）；扫描耗时不因界面刷新而显著增加。

## C-04 减少回调

- **改动点 → 类型**：进度投递链路 → **修改**（性能改进）。
- **现状**：
  1. 进度回调在 1MiB 分块循环内触发 → 一次扫描投递成千上万个排队界面事件；
  2. `MainWindow::setTransientMessage()` 每次都调用 `setStyleSheet()`。
- **新增/修改/删除**：**修改**
  - 工作线程的进度回调**只更新原子变量**（不投递界面事件、不直接操作界面）；
  - 进度回调**粒度粗化**（不再按 1MiB 分块触发，改为按区域或更低频）；
  - 刷新瞬时信息时**不重复重设样式表**（仅在状态类别变化时更新样式）。
- **影响窗口/功能**：状态栏瞬时文字、扫描 ViewModel 回调。涉及 `MainWindow::setTransientMessage`/`setProgress`。
- **窗口布局**：不变。
- **用户操作路径（点击流程）**：选择进程 → 点击「扫描」→ 界面无卡顿，扫描不因刷新变慢。
- **可视化反馈**：状态栏文字/进度平滑更新，无闪烁、无卡顿。
- **验收**：扫描期间排队的界面事件数量与进度刷新次数为同一量级（约每秒数次），不再出现"成千上万"积压；`setStyleSheet` 不在每次刷新时调用。

## C-05 不新增区域权限过滤（范围界定）

- **改动点 → 类型**：范围界定（**不新增**）。
- **决策**：**不**新增「按可读/可写/可执行过滤区域」的选项。
- **理由**：可读是扫描前提；按可写/可执行过滤有**漏报**风险，漏掉命中比扫得慢更糟糕。现有 `atomic::IsReadableProtect()` 只保留可读区域的语义正确，保持不变。
- **影响窗口/功能**：无（不产生 UI 与 API 变更）。
- **验收**：界面与 psig 公共 API 中均**不存在**区域权限过滤选项。

## 优先级与依赖

- 静态库依赖：**C-01、C-02、C-04（回调粒度）** 需先改 psig（进度语义、区域并行、回调粒度）；**C-03、C-04（界面侧）** 为纯 GUI。
- 建议顺序：psig（C-01 进度语义 → C-02 区域并行 → C-04 回调粒度）→ GUI（C-03 定时器 → C-04 原子变量与样式）→ 回归测试。

## 排除项（本步不做）

- 不新建窗口/页面、不改窗口层次。
- 不改技术栈。
- 不改变扫描语义（命中判定、结果字段、导出格式）。
- 不新增区域权限过滤选项（C-05）。
- 不删除 psig 公共 API。
