# 14 API 能力需求分析（v0.3.0，增量）

- 模式：修改型。聚焦 v0.3.0 改动点新增/变更的静态库能力需求。
- 既有静态库：`psig`（公开 API 见 `psig/include/psig.h`）。

## 能力需求清单

### R-01 进度反映真实工作量（C-01）
- **期望能力**：`psig::ScanProcesses` 的进度回调所报 `ScanProgress` 应反映**真实扫描进度**：`total` = 本次扫描总工作量（所有目标进程可读区域数之和），`done` = 已完成工作量，随扫描**单调递增**，结束达到 `done == total`。
- **期望公共 API**：**签名不变** —— `struct ScanProgress { uint32_t currentPid; size_t done; size_t total; size_t hits; };`（`done`/`total` **语义修正**：由「已处理模式数/总模式数」改为「已完成工作量/总工作量」）。
- **行为**：回调中 `done` 单调不减；`total` 在扫描期间为常量（预统计得出）；扫描结束时 `done == total`。
- **输入/输出**：无新增输入 → 回调参数数值语义修正。
- **异常要求**：不抛异常；无区域时 `total==0`，GUI 侧按 0 处理。
- **验收标准**：单进程多区域扫描，进度值从 <100 单调增到 100；不再恒为 100。

### R-02 区域级并行扫描（C-02）
- **期望能力**：`psig::ScanProcesses` 内部以**内存区域**为并行单位，用多个工作线程并发扫描，缩短总耗时；结果、进度、取消并发安全。
- **期望公共 API**：**签名不变** —— `std::vector<MatchResult> ScanProcesses(const ScanRequest&, ProgressCallback, const std::atomic_bool*);`（实现内部并行化）。
- **契约变更（非签名）**：
  - 进度回调**可能被多个工作线程并发调用**（GUI 侧回调必须线程安全——仅写原子变量即可）；
  - 返回的 `MatchResult` **顺序不保证**与串行版本相同（内容/数量一致）；
  - `maxResultsPerPattern`（每模式命中上限）在并行下仍需**逐模式**保证不超过上限（实现需协调）。
- **输入/输出**：输入不变 → 输出内容不变（顺序可变）。
- **异常要求**：不抛异常；线程创建失败时回落串行执行，不失败。
- **验收标准**：多核机器上同一任务并行版本耗时明显低于串行版本；命中集合与串行版本一致（数量与内容相同）。

### R-03 进度回调粒度粗化（C-04）
- **期望能力**：进度回调**不再按 1MiB 分块触发**，改为按「区域」或更粗粒度触发，减少回调次数。
- **期望公共 API**：**签名不变**（`ProgressCallback` 类型不变；触发频率降低）。
- **行为**：一次典型扫描的回调次数由「与 1MiB 块数同量级」降为「与区域数同量级或更低」。
- **验收标准**：大区域扫描时回调次数显著下降（可统计），且不影响进度可见性（配合 GUI 定时采样）。

### 无需静态库变更的改动点
- **C-03 定时采样**：纯 GUI（`QTimer` 读取原子变量）。**无需 psig 变更**（回调仍按 R-03 提供）。
- **C-04 界面侧回调削减**：GUI 侧回调改为只写原子变量、样式表条件化。**无需 psig 变更**。
- **C-05 区域权限过滤**：不新增。**无需 psig 变更**（`IsReadableProtect` 语义保持）。

## 能力覆盖判定

| 需求 | 现有 psig API 是否覆盖 | 处置 |
| --- | --- | --- |
| R-01 进度语义 | 否（语义错误） | 走静态库流程修正 `ScanProgress` 取值 |
| R-02 区域并行 | 否（当前串行） | 走静态库流程实现内部并行化 |
| R-03 回调粒度 | 否（当前按 1MiB） | 走静态库流程粗化回调触发 |

- 均为**既有 API 的行为修正/实现改进**（签名不变），`psig` 已存在，无需新建库，但需走「静态库跨流程需求接收」（步骤 20）。
- GUI 不直接实现缺失功能、不调用平台 API；全部经由 `psig` 公共 API。
