# 16 API 充分性审查（v0.3.0）

> 前置：`14_API能力需求.md`、`psig/include/psig.h`
> 目标：审查 psig 公开 API 是否满足全部改动需求并支持并发调用。

## 1. 逐能力审查

| 能力 | 现有公共 API | 满足？ | 结论 |
| --- | --- | --- | --- |
| R-01 进度语义（C-01） | `ScanProcesses(req, progress, cancel)` + `ScanProgress{done,total}`（内部把 `done`/`total` 都填为模式数） | **否** | 需修正取值：`total`=总工作量、`done`=已完成工作量，单调递增 |
| R-02 区域并行（C-02） | `ScanProcesses(...)`（当前进程×区域双重串行） | **否** | 需内部以区域为并行单位实现多线程扫描 |
| R-03 回调粒度（C-04） | `ProgressCallback`（当前在 1MiB 分块内触发） | **否** | 需粗化触发粒度（按区域或更低频） |
| C-03 定时采样 | `ProgressCallback`（保留） | 是（psig） | GUI 侧 `QTimer` 读原子变量即可，无需 psig 变更 |
| C-04 界面侧回调削减 | `ProgressCallback`（保留） | 是（psig） | GUI 侧回调只写原子变量、样式表条件化，无需 psig 变更 |
| C-05 区域权限过滤 | `atomic::IsReadableProtect`（保持只读区域） | 不需要 | 不新增；语义保持 |
| （既有）枚举/解析/扫描/图标/导入导出 | `EnumerateProcesses`/`ParsePattern`/`ScanProcesses`/`ProcessIcon`/`Import*`/`Export*` | 是 | 直接调用，行为不变（除本次扫描改进） |

## 2. 并发审查

- 现有 `ScanProcesses` 已支持取消标志与进度回调，回调在后台线程触发。
- **本次引入内部并行**：R-02 使进度回调**可能被多个工作线程并发调用**。契约要求：
  - 回调实现必须**线程安全**（GUI 侧仅写 `std::atomic`，满足）；
  - 结果汇聚、进度计数、取消轮询在库内并发安全。
- 公开 API 签名不变；并发调用语义增强（库内部并行）。
- 结论：并发调用无阻碍（需在契约中声明回调可并发触发、结果顺序不保证）。

## 3. 审查结论

- **不满足**：R-01、R-02、R-03 需静态库变更。
- 处置：进入 **缺失能力分析（步骤 19）**，生成缺失需求并触发**静态库流程调用（步骤 20）**。
- 约束确认：
  - ViewModel 只直接调静态库公共 API；匹配对象只能是 psig 公共 API，**禁止用 OS API 充当能力提供方**。
  - 禁止在 GUI 中自行实现缺失能力（尤其**不得**在 GUI 侧自建线程池绕过 psig）；在静态库完成契约返回前，GUI 停止 ViewModel 层相关编码。

## 4. 约束满足说明

- 已审查全部改动能力；不足 → 跳转静态库流程补充（见 17/18 文档）。
