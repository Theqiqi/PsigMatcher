# 18 静态库流程交接记录（v0.3.0）

> 前置：`17_API缺失需求.md`

## 1. 交接原因

GUI 改动点 C-01（进度条恒 100%）、C-02（区域并行）、C-04（回调过密）需要「进度语义修正」「区域级并行扫描」「进度回调粒度粗化」能力，`psig` 现有公共 API **不覆盖**（见 `16_API充分性审查.md`）。

## 2. 交接内容（逐项）

| 缺失能力 | 期望公共 API | 输入 | 输出 | 异常要求 | 验收标准 |
| --- | --- | --- | --- | --- | --- |
| M-1 进度语义 | `ScanProgress.done/total` 取值修正（签名不变） | 无 | 回调报真实工作量，单调递增 | 不抛异常；无区域时 total=0 | 进度由 <100 单调增到 100，不再恒 100 |
| M-2 区域并行 | `ScanProcesses(...)`（签名不变，内部并行） | 无 | 结果内容/数量与串行一致（顺序可变） | 不抛异常；区域级错误隔离；线程失败回落串行 | 多核耗时明显低于串行；命中集合一致 |
| M-3 回调粒度 | `ProgressCallback` 触发频率降低（签名不变） | 无 | 回调次数显著下降 | 不抛异常 | 回调次数降为区域数同量级或更低 |

## 3. 约束

- 静态库实现必须使用真实底层能力（WinAPI `ReadProcessMemory` / 标准库线程），**禁止**模拟数据、硬编码结果或伪造 API。
- 静态库**不依赖 Qt**：区域并行只能用标准库线程设施（`std::thread`/`std::async` + `std::mutex`/`std::atomic`），不得使用 `QThread`/`QtConcurrent`。
- 静态库流程完成后必须输出**静态库完成契约**，并**跳回** GUI 流程的「静态库完成回退检查（步骤 21）」，不得直接跳到 GUI 接口实现。
- GUI 在契约返回前**停止 ViewModel 层相关编码**（进度取值、定时采样、回调改写）。
