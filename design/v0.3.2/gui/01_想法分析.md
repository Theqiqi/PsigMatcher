## 三、逐条分析与期望行为

### C-01 「未保存」不是真的检测，而是固定条件

- **现状（两处不真实）**：
  1. **单元格编辑未计入未保存**。`SignatureTableModel::setData`（`gui/src/model/signaturetablemodel.cpp:30-39`）在用户编辑单元格后 `emit dataChanged(...)`；但 ViewModel **从未连接**该信号（`grep -rn 'dataChanged' gui/src/viewmodel` → 无命中）。因此用户直接在表里改内容（特征码编辑页的主要操作）后 `m_sigDirty` 仍为 `false`。
  2. **导入前提示用固定条件**。`MainViewModel::onImportSignatures`（`gui/src/viewmodel/signature.cpp:73`）以 `m_sigModel->rowCount() > 0`（表非空）作为「可能未保存」的判据，文案也是「**可能**未保存」——与是否真的改过无关。
- **表现**：明明改了内容却不认为有未保存改动（不提示、关闭即丢）；反之仅因表非空就提示保存。
- **期望**：未保存状态由**真实改动**驱动——任何使特征码表内容偏离「上次保存/导入/导出」的操作（含单元格编辑、增行、删行、改列定义）都置 `m_sigDirty=true`；导入/导出成功置 `false`；所有未保存提示统一以 `m_sigDirty` 判定。

### C-02 未保存提示的触发把「导入」与「保存/导出」缝在一起

- **现状**：`onImportSignatures`（`signature.cpp:73-95`）在开始导入前，若表非空即弹「导入前确认：当前特征码表**可能**未保存，是否先保存？」并提供 [保存 / 不保存 / 取消]；其中「保存」实际执行的是**导出**（`exportSignaturesToPath` → 弹另存为文件对话框），保存完成后**紧接着**弹出导入的「选择文件」对话框。
- **表现**：用户点「导入特征码」，却先被要求「保存/导出」，保存后马上又弹一个输入对话框——两个本应独立的用户流程被缝合，心智模型错位。
- **期望（用户确认）**：**导入与保存/导出解耦**——导入前**仅做覆盖确认**（且仅在**真的有未保存改动**时）：文案「当前特征码表有未保存改动，导入将覆盖它。是否继续？」，按钮 **[继续导入 / 取消]**，**不再提供保存/导出选项**。保存/导出只属于导出流程。
- **范围**：仅 `onImportSignatures`。「重新选择进程」（`askSaveSignatureChanges`）与「关闭程序」（C-03）是**丢弃/导航**动作，保留「保存 / 不保存 / 取消」提示（不属于导入/导出）。

### C-03 关闭程序时缺少未保存提示

- **现状**：`MainWindow` 无 `closeEvent`，`MainViewModel` 无关闭处理（`grep -rn 'closeEvent\|aboutToQuit' gui/src` → 无命中）；关闭程序时未保存的特征码改动被静默丢弃。此外文件菜单「退出」的 `m_quitAction` **从未 connect**（`grep -rn 'quitAction' gui/src` → 仅创建与加菜单），点「退出」实际无任何效果。
- **期望**：关闭窗口/点「退出」时若特征码表有未保存改动，弹窗提示 [保存 / 不保存 / 取消]；「取消」**阻止关闭**（窗口保持打开）；「保存」走另存为文件对话框，成功后才关闭。同时把「退出」动作连接到关闭，使其真正生效并复用同一提示。
- **实现边界**：View 层**不含事件处理逻辑**（`design/v0.3.1/gui/29_View层审查矩阵.md` 的 View 检查项），故关闭判定放在 **ViewModel 的事件过滤器**中（ViewModel 允许「持 View 指针链接事件」）。

### C-04 程序名 `psig_gui.exe` 像 demo 名

- **现状**：生产目标名 `psig_gui`（`gui/CMakeLists.txt`、`gui/src/CMakeLists.txt`）、入口 `QApplication::setApplicationName("psig_gui")`、翻译资源名 `psig_gui_*.ts`、E2E/校验脚本中的 `psig_gui.exe`、_target 目标 `psig_gui_target`。
- **期望（用户确认）**：程序正式名 **`PsigMatcher.exe`**（保留 `psig` 产品前缀 + 「匹配器」语义）；界面标题仍为「进程特征码批量匹配器」（版本号随本版更新为 v0.3.2）。改名需同步：构建目标与 `project()`、入口 `setApplicationName`、i18n 资源名与装载路径、风格表注释、校验/E2E 脚本、测试 target。

## 四、本轮已澄清的设计决策（用户确认）

| 议题 | 决策 |
| --- | --- |
| C-01 未保存判定 | **真实脏标记**：连接模型 `dataChanged`，单元格编辑计入未保存；提示一律以 `m_sigDirty` 判定（替换导入前的 `rowCount()>0`） |
| C-01 可见性 | 未保存时持久状态区追加 `*` 标记，使真实状态可见（瞬时区/日志仍承担操作反馈） |
| C-02 导入提示 | **仅覆盖确认**：有未保存改动时提示 [继续导入 / 取消]，**无保存/导出选项** |
| C-03 关闭提示 | **新增**：关闭/退出时有未保存改动则提示 [保存 / 不保存 / 取消]；「取消」阻止关闭 |
| C-04 程序名 | **`PsigMatcher.exe`** |
| 「保存」行为 | 仍走「另存为」文件对话框（用户确认该对话框本身没问题，问题在触发时机）；**不引入「当前文件路径」概念** |

## 五、不做的事（排除项）

- 不新建程序、不新增窗口/页面。
- 不改技术栈（沿用 Qt6::Widgets / Qt6::Concurrent / MSVC+Ninja / vcpkg）。
- **不改静态库 `psig`**（无新 API、无源码改动）。
- 不改变特征码/结果导入导出的文件格式与往返语义（沿用 v0.3.1）。
- 不引入「当前文件路径」/静默覆盖保存；不改变「重选进程」提示的语义。
- 不为「结果页」引入未保存概念（结果页是扫描输出，无持久化语义）。
