# 13 技术选型分析（v0.3.2，增量）

- 版本：v0.3.2
- 模式：修改型。**沿用既有技术栈，不重新选型**。

## 一、结论：沿用

| 项 | 选型（沿用） | 本版是否变化 |
| --- | --- | --- |
| 语言 | C++20 | 否 |
| 窗口框架 | Qt6::Widgets（代码构建 Widget） | 否 |
| 异步 | Qt6::Concurrent（`QtConcurrent::run` + `QFutureWatcher`） | 否 |
| 平台 | Windows 桌面 exe（MSVC 工具链） | 否 |
| 构建 | CMake + CMakePresets（Ninja 生成器） | 否（仅改目标名） |
| 包管理 | vcpkg manifest（gtest；Qt 独立安装不纳入） | 否 |
| 测试 | gtest + Qt6::Test（QSignalSpy/QTRY_VERIFY） | 否 |
| 静态库 | `find_library` 引用 `../psig/out/lib/<配置>/psig.lib`，公共头 `../psig/include/psig.h` | 否 |

## 二、本版相关的技术点确认

- **C-01 真实脏标记**：使用 Qt 既有 `QAbstractItemModel::dataChanged` 信号 + ViewModel 槽（`bind*` 集中连接），不引入新技术。
- **C-02/C-03 模态确认**：使用 Qt `QMessageBox`（既有用法），并为按钮设置 `setShortcut` 提供确定性键盘入口（既有约定的延伸，见 `05_GUI功能列表与窗口定义.md`）。
- **C-03 关闭拦截**：使用 Qt 既有 `QObject::installEventFilter` + `QEvent::Close`（ViewModel 侧实现，避免 View 含事件处理逻辑），不引入平台 API。
- **C-04 改名**：仅改 CMake 目标名/入口 `setApplicationName`/i18n 资源名；技术栈不变。

## 三、约束满足说明

- 默认技术选型（C++20 / Qt6::Widgets / Qt6::Concurrent / Windows / CMake / vcpkg）保持不变；已确认既有技术栈仍满足本版需求，标注「沿用」，不重复分析。
